Login, then invite

Five stages turn a UID and password into a game session: grant, MajorLogin, address lookup, auth blob, and the raw TCP invite.

01

Five-stage handshake

Every account goes through the same five stages. Bodies are hand-built protobuf messages encrypted with AES-128-CBC/PKCS5 using a static key and IV compiled into Proto.kt. There is no certificate pinning.

Guest token grant

POST · ffmconnect.ppmainecoonghj.com

The app posts the account UID and password to an OAuth endpoint. The host is not a Garena-owned name; this is the credential-egress point.

request shapesecrets redacted
POST /api/v2/oauth/guest/token:grant

{
  "client_id": 100067,
  "client_secret": ‹static›,
  "client_type": 2,
  "uid": ‹account uid›,
  "password": ‹account password›,
  "response_type": "token"
}

Response: data.access_token and data.open_id.

MajorLogin

POST · loginbp.ggpolarbear.com

The grant result is expanded into a large device-metadata protobuf, AES-encrypted with the static key, and posted to the login service.

Api.kt · MajorLogin body
val body = proto {
  str(3, now());  str(4, "free fire");  int(5, 1)
  str(7, "1.126.8")
  str(19, "Google|${openId.take(36)}")
  str(22, openId); str(26, "BD")
  str(29, accessToken)
  // device, carrier, GPU, spoofed IP, counters…
}

The response carries the account ID, JWT, base URL and a per-session AES key/IV.

GetLoginData

POST · <base>/GetLoginData

The same encrypted body is sent to the returned base URL with the new JWT as a bearer token. Field 14 in the response is the game server address.

address extraction
val login = postAes("${major.base}/GetLoginData",
                    authBody, bearer = major.jwt)

val hostPort = login.field(14)   // "ip:port"
val ip   = hostPort.substringBefore(":")
val port = hostPort.substringAfter(":").toInt()

Auth blob

binary · written to the game socket

The session JWT is encrypted with the per-session key/IV and packed into a hex-framed blob. This is the first thing written to the TCP socket.

authHex · simplified
"0115"
  + zeroPad(hex(accountId), typically 16)
  + twoHexChars(timestamp)
  + "00000"
  + twoHexChars(byteLength(encJwt))
  + encJwt

The blob is not an HTTP header. It is raw bytes on the game port.

TCP invite

TCP · ip:port · 10 s connect / 4 s read

After the auth blob, the client drains login frames, sends a ready frame, waits one second, then writes the invite frame once per requested invite.

inviteFromAccount · simplified
connect(ip, port, 10_000); soTimeout = 4_000
write(authHex); flush
repeat(20) { drain() }
write(packet(type=1, groupMode))
delay(1_000)
repeat(count) {
  write(packet(type=2, targetUid, region, 4))
}

03

The auth blob

The blob is built once per account and reused for the TCP connection. It encodes the account ID, a timestamp, the encrypted JWT and a length prefix.

authHex constructionbinary framing
"0115"
  + zeroPad(hex(accountId), typically 16)   // 8-byte account id
  + twoHexChars(timestamp)                  // session timestamp
  + "00000"
  + twoHexChars(byteLength(encJwt))         // length prefix
  + encJwt                                  // AES(jwt, sessionKey, sessionIV)
Auth blob segments
SegmentPurpose
0115Protocol / packet marker
accountIdZero-padded hex identity
timestampTwo hex characters from the login timestamp
00000Fixed padding
lengthByte length of the encrypted JWT, hex-encoded
ciphertextAES-CBC encrypted session JWT
04

Invite path

There are two social primitives. Friend requests go over HTTPS; invites go over the raw game socket after the auth handshake.

Api.kt · friend request and TCP invitegroupMode 2 = duo · 3 = squad
// HTTPS friend request
POST "${base}/RequestAddingFriend"
Authorization: Bearer ‹jwt›
body = AES(proto { 1: senderAccountId,
                   2: targetUid,
                   3: 1 })

// raw TCP invite
socket.connect(InetSocketAddress(ip, port), 10_000)
socket.soTimeout = 4_000
socket.write(authHex.hexToBytes()); flush
repeat(20) { drain() }                  // consume login frames
socket.write(packet(type=1, groupMode))     // ready frame
delay(1_000)
repeat(count) {
  socket.write(packet(type=2, targetUid, region, 4))
}

Invite preparation uses the same HTTPS endpoint with operation code 26 before the TCP invite. The friend path uses 1.

05

Packet framing

Game packets are framed as a packet type, a five-character hex length, and the AES-encrypted protobuf body.

frame layout
packetType + 5 hex length chars + AES(protobuf)

// example shape, not live bytes
"0519" + "0012a" + ‹ciphertext›

The first packet nests group mode and client build metadata; the second names the target UID and region. Both are encrypted with the per-session key returned by MajorLogin.
