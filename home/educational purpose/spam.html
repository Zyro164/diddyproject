The spam engine

Thirty threads pull accounts from a shuffled queue, log in, and send one social action before the next. There is no backoff and no per-target limit.

01

Worker model

MainActivity holds a hardcoded pool size of 30. Each worker pulls the next account from a shuffled copy of the loaded list, logs in, performs one action, sleeps, and repeats.

30Workersconcurrent threads
40–120 msAction delayrandom per iteration
4CountersREQ · DUO · SQUAD · FAIL
0Backoffno per-target rate limit

The account list is shuffled once, then consumed with an atomic cursor. There is no rotation guard, no per-account cooldown, and no target-side rate limiting. The bottleneck is Garena login latency, not the device.

02

The loop

MainActivity.kt · spamLoopreconstructed and simplified
val queue  = accounts.shuffled()
val cursor = AtomicInteger(0)
val workers = 30

repeat(workers) {
  thread {
    while (running) {
      val acc = queue.getOrNull(cursor.getAndIncrement()) ?: break
      val info = Api.loginAccount(acc.uid, acc.password)
      if (info == null) { fails++; continue }

      when (mode) {
        0 -> send((1..3).random(), info)      // AUTO
        1 -> Api.sendFriendRequest(info, target)
        2 -> Api.invite(info, target, groupMode = 2) // DUO
        3 -> Api.invite(info, target, groupMode = 3) // SQUAD
      }
      delay(40..120)
      publishCounters(req, duo, squad, fail)
    }
  }
}

Log lines are emitted every 10 successes. The UI fill bar is driven by the number of threads started, not by completed work.

Sender selection

The account picker offers the bundled dump (DEFAULT UID) or every account saved in GenAccount.txt. Anonymous mode is not offered.

Target input

The target must be a numeric UID. A nickname lookup runs first so the operator can confirm the target before starting the loop.

05

Impact

Effect on the target

The target receives friend requests and duo/squad invites from a large rotating set of accounts. This is notification and request flooding. It does not change match state, currency, inventory, or account ownership.

For the operator, the interesting part is not the loop itself but the supply chain behind it: a bundled dump, a working login protocol, and a generator that can mint replacements. That is what the next two sections cover.
