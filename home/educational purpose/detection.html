Detection and response

The most important finding is not the spam loop. It is the endpoint that receives account UID and password, and the indicators that follow from it.

01

Weaknesses

The app is not obfuscated in any meaningful way. Protocol constants, keys, endpoints and the operator’s reseller token are readable after a standard decompile.

02

The critical finding

Credential harvesting pattern

The token endpoint is not a Garena-owned name. A tool that sends account UID and password to an unofficial domain is a credential-harvesting pattern, regardless of whether it also spams. Any real account used through it should be considered exposed.

This matters even if you ignore the spam feature entirely. The app collects a password, forwards it to a third party, and then uses the returned token for its own actions. The same design would work as a standalone harvester.

04

If it is installed

  1. Remove overlay and all-files permissions, then uninstall the package.
  2. Change the Garena / Free Fire password and revoke active sessions on every linked account.
  3. Check for unexpected linked logins, friend requests, and generated-account activity.
  4. Delete GenAccount.txt and any Telegram bot the app was configured with.
  5. Report the sample, package, certificate hash, and channel to Garena support and Telegram abuse.
Order matters

Rotate credentials before uninstalling if the device is shared or the app may have already exfiltrated the file. Uninstalling stops future runs; it does not revoke tokens already delivered.

05

Hunting

  • Alert on the package name, certificate hash, or the accounts1.json asset hash in app inventories.
  • Look for the overlay + MANAGE_EXTERNAL_STORAGE + FOREGROUND_SERVICE_SPECIAL_USE combination on gaming devices.
  • Watch DNS/TLS for the non-Garena token host and for repeated Telegram sendDocument calls from mobile clients.
  • Do not blanket-block Garena domains; scope network rules to the package or device group.
Defensive value

Because the protocol is static and unencrypted at the app layer, defenders can fingerprint the client by its MajorLogin field pattern, its fixed device strings, and its unusual token host — even when the IP changes.
