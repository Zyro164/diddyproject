Recovered source

The app package is seven files. The protocol layer is readable, the field numbers are intact, and the sensitive constants are still in the binary.

01

Source map

The APK is Kotlin, R8-compiled, and was recovered with JADX. The app package is tiny; the remaining classes are libraries. The decompiled tree lives in a scratch workspace and is not reproduced here because it contains live credentials and keys.

03

What survived decompilation

Readable

  • Method names and control flow.
  • Protobuf field numbers and constants.
  • Endpoints, headers and packet types.
  • Static keys, tokens and device strings.
  • Assets and preference names.

Reconstructed

  • Kotlin object / data class structure.
  • Default arguments and nullability.
  • Inline helper names and formatting.
  • Some compiler-generated lambdas.
  • Comments and original formatting.

JADX emits Java, not Kotlin. The metadata annotations and compiled from: lines prove the original language, but the exact Kotlin syntax is not recoverable.

04

Decompiler notes

Coverage

JADX reported 89 method-level decompilation errors across the whole APK, mostly in library code and synthetic methods. The seven app-specific files disassembled cleanly, and the flow is corroborated by strings, the manifest, and the network field values.

Line counts refer to the recovered Java files, not the original Kotlin sources. The scratch tree is intentionally excluded from this site.
